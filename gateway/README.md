# Kimi Control: защищённое подключение

Этот каталог содержит **необязательный бесплатный шлюз** к официальному Kimi Code CLI. Никакой отдельной подписки на шлюз нет. Расходы на модель Kimi и сервер остаются отдельными.

## Что готово

- Android обращается к HTTPS адресу и передаёт только **отдельный мобильный токен**, а не серверный токен Kimi;
- шлюз локально пересылает разрешённые операции Kimi REST API;
- поддержаны подключение, сессии, история, отправка промптов, фото/файлов, разрешения действий, скачивание файлов проекта;
- все другие методы, включая прямой доступ к произвольным файлам хоста, запрещены;
- токен в Android хранится через Keystore;
- тесты маршрутов: `python3 -m unittest discover -s gateway -v`.

## Что ещё требуется перед подключением с телефона

1. **На CONTROL** — проверить актуальную версию Kimi Code CLI, учётную запись, рабочую директорию, свободный порт и существующие службы.
2. Запустить Kimi Code локально в отдельной учётной записи без root:

   ```sh
   kimi web --host 127.0.0.1 --port 58627 --no-open
   ```

   Команда показывает секретный токен. Не копируйте его в GitHub или переписку.

3. На том же сервере запустить шлюз с переменными окружения (значения **не публиковать**):

   ```sh
   export KIMI_SERVER_TOKEN='<server-token-from-kimi-web>'
   export KIMI_MOBILE_TOKEN='<independent-random-token-min-32-chars>'
   export KIMI_LOCAL_PORT=58627
   python3 gateway/kimi_gateway.py
   ```

   Пример генерации случайного токена: `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'`.

4. Существующий доверенный HTTPS-вход должен пересылать трафик **только** на `127.0.0.1:8765`. Не публиковать открытый HTTP порт 8765 или сырой Kimi порт 58627. HTTPS с действительным сертификатом обязателен. Установить ограничение частоты запросов, доступ только доверенному телефону/сети и разумный лимит загрузки. **Не внедрять без анализа существующего production.**
5. В Android → Настройки указать HTTPS адрес, путь рабочей директории на сервере и отдельный `KIMI_MOBILE_TOKEN`. Нажать «Сохранить и проверить». Если сервер доступен и отвечает правильно — появятся сессии.

**Важные ограничения:**
- API Kimi экспериментальный. Перед использованием проверить `/openapi.json` живой версии локально, без публикации токена;
- шлюз сейчас поддерживает REST и периодическое обновление истории, но не WebSocket live-stream и не полный спектр интерактивных вопросов/задач;
- шлюз не должен запускаться под root или иметь доступ к VPN production-файлам;
- REST разрешения действий следует оставлять в режиме ручного подтверждения, не включать автоматическое выполнение;
- приложение не должно подключаться непосредственно к открытому Kimi Server API: тот предоставляет крайне широкие полномочия.

Проект **не меняет** конфигурацию действующих серверов. Внедрение шлюза — отдельный этап после чтения текущего состояния и бэкапа.

Официальная документация: https://www.kimi.com/code/docs/en/kimi-code-cli/reference/server-api.html
