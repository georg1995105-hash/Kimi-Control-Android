# Kimi Control — нативный Android-клиент для Kimi Code

**Версия 0.2: клиент и защищённый шлюз находятся в исходном коде.** Приложение уже успешно компилировалось в GitHub Actions. Реальное соединение с CONTROL пока не развёрнуто и сквозное тестирование с Kimi Code не пройдено.

## Функции, реализованные в исходниках

- Нативный Kotlin / Jetpack Compose с русскоязычным адаптивным интерфейсом, адаптивной иконкой и корректными Android inset-отступами.
- Подключение через HTTPS к **ограниченному шлюзу**, который проксирует официальный локальный Kimi Code CLI REST API.
- Проверка подключения, создание сессии, список сессий, история, отправка пользовательских задач.
- Отправка фотографий и документов до 30 МБ каждое через стандартный Android picker.
- Отображение ожидающих разрешений агента и кнопки «Разрешить» / «Отклонить».
- Скачивание файла из рабочего каталога сессии через системное сохранение Android (до 100 МБ); подсказки о файлах по именам в ответе.
- Диктовка на русском языке `ru-RU`, с редактированием распознанного текста перед отправкой.
- Защищённое хранение токена в Android Keystore. Автоматическое восстановление подключения при запуске.
- Автоматическая GitHub Actions сборка APK и тесты маршрутов шлюза.

**Не реализовано / не подтверждено:** WebSocket-стриминг ответов в реальном времени (пока REST-проверка каждые 5 секунд, когда приложение открыто), полноценный вывод всех команд и диффов, обработка вопросов агента, фоновые уведомления, надёжная обработка многогигабайтных вложений, сквозное тестирование с настоящим Kimi на CONTROL и подлинным Vivo X300 Pro.

## Важное: обновления APK поверх установленной версии

**Debug APK из разных запусков GitHub Actions не гарантирует совместимую подпись.** Из-за этого старые тестовые версии могли не обновляться поверх друг друга.

Добавлен отдельный workflow **Stable signed APK**:
- он использует постоянный RSA-ключ подписи Android (сертификат не меняется между сборками);
- в первый запуск после настройки секрета генерирует ключ и коммитит в публичный репозиторий **только зашифрованный контейнер** (`signing/release-key.p12.enc.b64`), без открытого приватного ключа;
- ключ шифруется AES-256-CBC с PBKDF2 (250 000 итераций), секрет расшифровки хранится **только в GitHub Actions Secrets**;
- в `versionCode` используется номер запуска workflow плюс 1000, который увеличивается при новых сборках;
- готовый артефакт называется **Kimi-Control-STABLE-SIGNED-APK** и проходит проверку `apksigner verify`.

**Один обязательный шаг владельца репозитория:** в GitHub Settings → Secrets and variables → Actions → New repository secret создать `KIMI_SIGNING_PASSWORD` (случайный секрет длиной не менее 32 символов), затем запустить workflow **Stable signed APK** через Actions → Run workflow. Никогда не публиковать секрет в README, коммитах или issue.

Первую подписанную stable-версию придётся установить вместо прежнего debug APK: Android не позволяет заменить приложение, подписанное другим ключом. После этого версии с одним и тем же stable-ключом будут устанавливаться поверх друг друга при увеличении versionCode, сохраняя данные.

**Если потерять `KIMI_SIGNING_PASSWORD`, восстановить этот ключ будет невозможно**, поэтому сохранить резервную копию секрета вне GitHub. Для пользовательских обновлений скачивать только **STABLE-SIGNED-APK**, а не Debug APK.

## Установка APK

Для обычной установки и будущих обновлений используйте [Actions](../../actions) → **Stable signed APK** → Artifacts → **Kimi-Control-STABLE-SIGNED-APK**. Пока секрет подписи не настроен, подписанный APK не публикуется; debug сборки остаются исключительно для разработки.

## Подключение

Проект не содержит реальных IP, токенов, SSH-ключей, доменов и секретов. Для удалённого доступа требуется подготовить отдельный контур Kimi Code и шлюз: [gateway/README.md](gateway/README.md). Сначала проверить состояние существующего CONTROL, затем настроить HTTPS и авторизацию, **не открывая** Kimi Code в интернет.

Пользователь Android после подготовки защищённого адреса сможет открыть **Настройки → Подключение**, ввести адрес, рабочую папку и мобильный токен, затем нажать «Сохранить и проверить». Для работы с моделью остаётся нужна её собственная действующая авторизация; приложение не заменяет подписку или API-доступ Kimi.

## Почему API не включён напрямую

Официальный `kimi web` предоставляет доступ к командам и файлам машины. Сырой REST/WebSocket API нельзя безопасно выставлять на публичный адрес без ограничения полномочий. Прокси в `gateway/` разрешает лишь нужные мобильному приложению операции.

Официальная спецификация: https://www.kimi.com/code/docs/en/kimi-code-cli/reference/server-api.html

## Сборка

JDK 17 + Android SDK 35 + Gradle 8.13, команда: `gradle :app:assembleDebug`.

Приложение не собирает аналитику и не использует рекламные SDK. Исходный код публичный, приватные ключи не публиковать.
